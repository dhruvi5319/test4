Install the axe-core React integration (dev dependency only):

```bash
npm install --save-dev @axe-core/react axe-core
```

In `src/main.tsx`, add the axe initialization after the existing imports, guarded by development mode check:

```tsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App'
import './index.css'

// WCAG AA automated audit — only in development
if (process.env.NODE_ENV !== 'production') {
  const axe = await import('@axe-core/react')
  axe.default(React, ReactDOM, 1000)
}

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
)
```

Use dynamic `import()` so axe-core is never bundled in production. The `1000ms` delay gives the app time to render before the first audit runs.

Note for executor: @axe-core/react logs violations to the browser DevTools console under "axe" with rule IDs (e.g., `color-contrast`, `button-name`, `aria-required-attr`). After wiring, run the dev server (`npm run dev`), open the app, open DevTools console, and record any violations. Fix critical/serious violations in this task or Task 2.

Common violations to look for and fix inline:
- `color-contrast`: Any text below 4.5:1 ratio on current backgrounds → increase opacity or adjust Tailwind color class
- `button-name`: Any button without accessible name → add aria-label
- `aria-required-attr`: Missing required ARIA attributes → add them
- `landmark-one-main`: Ensure `<main>` element exists → wrap main content in `<main>` in AppShell if missing

**TemperatureTrendChart.tsx — Add visually hidden data table (FR-11 requirement):**

FR-11 specifies: "Provide a visually hidden `<table>` alongside the AreaChart containing the same temperature data for screen readers."

Read the existing TemperatureTrendChart component, then add a `<table className="sr-only">` element immediately after the `<ResponsiveContainer>` wrapper:

```tsx
{/* Screen reader data table — satisfies FR-11 chart accessibility */}
<table className="sr-only" aria-label="Weekly temperature trend data">
  <caption>7-day temperature forecast</caption>
  <thead>
    <tr>
      <th scope="col">Day</th>
      <th scope="col">High ({unit === 'metric' ? '°C' : '°F'})</th>
      <th scope="col">Low ({unit === 'metric' ? '°C' : '°F'})</th>
    </tr>
  </thead>
  <tbody>
    {chartData.map(({ day, high, low }) => (
      <tr key={day}>
        <td>{day}</td>
        <td>{Math.round(high)}</td>
        <td>{Math.round(low)}</td>
      </tr>
    ))}
  </tbody>
</table>
```

Adapt variable names to match what already exists in the component (chartData array with day/high/low fields, or equivalent). The table must render in the same component as the chart — not in a separate component.

Also add `aria-hidden="true"` to the `<ResponsiveContainer>` wrapper so screen readers skip the SVG paths and read only the table.

**HourlyForecast.tsx — Touch target audit (WCAG 2.5.8, 44px minimum):**

Each hourly card is currently `min-w-[72px] min-h-[110px]` — this exceeds 44px in both dimensions. Confirm this is correct. No changes needed if confirmed.

However, the cards are `<div>` elements, not interactive. They have `aria-label` but no `role="button"` or `tabindex`. If hourly cards are informational-only (not clickable), this is correct — they don't need to be interactive. If they are meant to be clickable (e.g., for drill-down), add `role="button" tabindex="0"` and keyboard handlers. Based on the current implementation (display-only), leave as non-interactive `<div>` with `aria-label` — this is acceptable.
