**CurrentConditions.tsx — Ensure aria-live region is always in DOM:**

FR-11 specifies: "Ensure aria-live div exists in DOM at all times (not conditionally rendered)."

Currently, CurrentConditions conditionally returns `<CurrentConditionsSkeleton />` or `<WeatherErrorCard />` early, so the `aria-live` wrapper is only rendered in the success state. Fix:

Restructure so a persistent `aria-live="polite" aria-atomic="true"` wrapper always renders, containing the appropriate inner content (skeleton, error, or data):

```tsx
export default function CurrentConditions({ location }: CurrentConditionsProps) {
  const { data, isLoading, isError, refetch } = useWeather(location.lat, location.lon)
  const { unit } = useUnitPreference()

  return (
    <div aria-live="polite" aria-atomic="true">
      {isLoading && <CurrentConditionsSkeleton />}
      {(isError || (!isLoading && !data)) && <WeatherErrorCard onRetry={() => refetch()} />}
      {data && !isError && <CurrentConditionsContent data={data} location={location} unit={unit} />}
    </div>
  )
}
```

Extract the success-state JSX into a `CurrentConditionsContent` sub-component (private, not exported) to keep the code clean.
