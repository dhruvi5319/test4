**WCAG contrast decisions:**
- White text (#ffffff) on backgrounds MUST achieve ≥ 4.5:1 contrast ratio.
- Light snow backgrounds (from-slate-200 to-blue-200) are too light for white text — use dark text (text-slate-900) OR darken the gradient so white text passes.
- For this implementation: darken snow gradients so white text passes. Use `from-slate-400 to-blue-400` (contrast ~4.5:1 for white).
- All sky-blue daytime gradients already pass for white text (sky-500 and above are dark enough).
- Night variants use dark indigo/slate — white text always passes.

/**
 * WCAG 1.4.3 contrast strategy: All gradients use white (#fff) text.
 * Minimum passing grade: Tailwind slate-500 (#64748b) on white = ~3.8:1 (fails for small text).
 * We use slate-500+ for gradient endpoints. The darkest colour in the gradient

**AppShell.tsx — add useWeather call + apply dynamic background:**

AppShell currently does not import or call `useWeather`. It holds `activeLocation` state but does not read weather data directly. We need the `weatherCode` and `isDay` from the current weather to pick the gradient.

**Strategy:** Call `useWeather(activeLocation?.lat ?? null, activeLocation?.lon ?? null)` inside AppShell. This reuses the cached TanStack Query result (same query key as child components) — no extra network request.

**Updated AppShell.tsx:**

```tsx
import { useState } from 'react'
import CurrentConditions from './components/CurrentConditions'
import DailyForecast from './components/DailyForecast'
import HourlyForecast from './components/HourlyForecast'
import LocationBar from './components/LocationBar'
import SettingsBar from './components/SettingsBar'
import WeatherDetails from './components/WeatherDetails'
import { useWeather } from './hooks/useWeather'
import { getWeatherCondition } from './utils/weatherCodes'
import type { Location } from './types/location'

export default function AppShell() {
  const [activeLocation, setActiveLocation] = useState<Location | null>(null)

  // Reuses TanStack Query cache from child components — no extra network call
  const { data: weatherData } = useWeather(
    activeLocation?.lat ?? null,
    activeLocation?.lon ?? null
  )

  // Derive background gradient class from live weather data
  // When no location is active or data hasn't loaded yet, use bg-slate-900
  const bgClass = (() => {
    if (!activeLocation || !weatherData) return 'bg-slate-900'
    const condition = getWeatherCondition(weatherData.current.weatherCode)
    const isDay = weatherData.current.isDay === 1
    const gradientClass = isDay
      ? condition.backgroundClass
      : condition.backgroundClassNight
    // bg-gradient-to-br applies the gradient direction; the from-/to- classes set the colours
    return `bg-gradient-to-br ${gradientClass}`
  })()

  return (
    <div className={`min-h-screen ${bgClass} text-white flex flex-col`}>
      <div className="max-w-2xl w-full mx-auto px-4 py-8 space-y-4 flex-1">
        {/* Location search + GPS */}
        <LocationBar
          onLocationSelect={setActiveLocation}
          currentLocation={activeLocation}
        />

        {/* °C / °F toggle */}
        <SettingsBar />

        {/* Weather content */}
        {activeLocation ? (
          <div className="space-y-4">
            <CurrentConditions location={activeLocation} />
            <HourlyForecast lat={activeLocation.lat} lon={activeLocation.lon} />
            <DailyForecast lat={activeLocation.lat} lon={activeLocation.lon} />
            <WeatherDetails lat={activeLocation.lat} lon={activeLocation.lon} />
          </div>
        ) : (
          <div className="text-center text-slate-400 py-20">
            <p className="text-xl font-medium mb-2">Simple Weather</p>
            <p className="text-sm">Search for a city or use your location to get started</p>
          </div>
        )}
      </div>

      {/* Attribution footer — Open-Meteo CC BY 4.0 required */}
      <footer className="text-center text-slate-500 text-xs py-4">
        Weather data from{' '}
        <a
          href="https://open-meteo.com"
          target="_blank"
          rel="noopener noreferrer"
          className="underline hover:text-slate-300 transition-colors"
        >
          Open-Meteo
        </a>
        {' '}(CC BY 4.0)
      </footer>
    </div>
  )
}
```

**Key implementation details:**
- `bg-slate-900` used when `activeLocation` is null OR weather data hasn't loaded yet (data is undefined). This prevents a flash of the wrong gradient before data arrives.
- `bg-gradient-to-br` is the gradient direction class. The `from-*` and `to-*` classes come from `condition.backgroundClass` or `condition.backgroundClassNight`.
- No CSS `transition` on the background — the class swap is instant. This inherently respects `prefers-reduced-motion` without needing to detect the media query.
- WeatherDetails is included here (from plan 03-02). If 03-02 runs in parallel and isn't complete, temporarily comment out the WeatherDetails import/usage and restore it after merge.
- The `useWeather` import is new to AppShell — add it.
- The `getWeatherCondition` import is new to AppShell — add it.

**Tailwind v4 note:** Tailwind v4 uses CSS-based configuration. Dynamic class composition (`bg-gradient-to-br ${gradientClass}`) works correctly as long as the class strings are complete Tailwind class names (e.g., `from-sky-400 to-blue-500`), not partial strings. All `backgroundClass` and `backgroundClassNight` values in WMO_CONDITIONS are complete, valid Tailwind class pairs. No safelisting is needed because these classes exist in weatherCodes.ts source files that Tailwind v4 will scan.
